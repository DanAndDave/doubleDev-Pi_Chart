# OKF (Open Knowledge Format) — research report

## What OKF is

**In its own words** (SPEC.md §preamble): "OKF is an open, human- and agent-friendly format for representing *knowledge*: the metadata, context, and curated insight that surrounds data and systems. It is designed to be authored by people, generated by agents, exchanged across organizations, and consumed by both." And: "The format is intentionally minimal: a directory of markdown files with YAML frontmatter. There is no schema registry, no central authority, and no required tooling. If you can `cat` a file, you can read OKF; if you can `git clone` a repo, you can ship it."

**Problem statement** (SPEC §1 Motivation): "The space of knowledge representation for AI agents is evolving quickly, and many incompatible conventions are emerging." Knowledge corpora are now "continuously written and maintained by agents", so a consumer needs five answers plain markdown+frontmatter does not make first-class: **provenance** ("What was this created from, and how was it verified?"), **trust**, **freshness**, **lifecycle**, **attestation** ("Was this number produced the way we said it must be?"). v0.2's contribution is making those first-class "while keeping the format minimally opinionated" and "without prescribing any runtime".

**Units of knowledge** (SPEC §2 Terminology, verbatim definitions):
- **Knowledge Bundle** — "A self-contained, hierarchical collection of knowledge documents. The unit of distribution."
- **Concept** — "A single unit of knowledge within a bundle, represented as one markdown document. It may describe a tangible asset (a table, an API), an abstract idea (a metric, a business process), or anything in between." ← this is *the* unit of knowledge.
- **Concept ID** — "The path of the concept's file within the bundle, with the `.md` suffix removed."
- Other defined terms: Frontmatter, Body, Link, Source, Provenance, Credibility signal, Actor, Trust tier, **Attested Computation**, Executor, Receipt, Attester.

The README frames the repo explicitly: "**This repository is primarily about the Open Knowledge Format (OKF)**… a **universal, vendor-neutral format**… **not tied to any particular agent, framework, model provider, or serving system**", with the BigQuery/Gemini reference agent and the HTML visualizer as "a **proof of concept** demonstrating *one* way to produce OKF bundles".

Goals (§1): define a universal format producers write into; inform how consumers read/traverse; facilitate cross-org exchange; standardize the small field set that makes an agent-maintained corpus trustable. Non-goals (§1): fixed taxonomy of concept types; storage/serving/query infrastructure; replacing Avro/Protobuf/OpenAPI ("OKF *references* them; it does not subsume them"); packaging/invocation standard for executor/attester code ("OKF fixes the interface, not the packaging").

## Format

**Serialization.** Markdown + YAML frontmatter. Extension `.md`, UTF-8. No JSON/protobuf/YAML-only variant exists. Frontmatter is "a YAML metadata block delimited by `---` at the top of a markdown file" (§2), opened and closed by `---` on its own line (§4). Body is free-form markdown; producers "SHOULD favor structural markdown (headings, lists, tables, fenced code blocks)".

**Bundle layout** (§3, verbatim):
```
path/to/bundle/
  index.md                      # Optional. Directory listing for progressive disclosure.
  log.md                        # Optional. Chronological history of updates.
  <concept>.md                  # A concept at the bundle root.
  <subdirectory>/               # Subdirectories organize concepts into groups.
    index.md
    <concept>.md
    <subdirectory>/
      ...
```
Distribution: git repo (recommended), tarball/zip, or subdirectory of a larger repo. Reserved filenames (§3.1): `index.md` (directory listing, §8) and `log.md` (update history, §9) — "MUST NOT be used for concept documents"; "All other `.md` files are concept documents."

**Required vs optional frontmatter** (§4.1):
- **Required:** `type` only — "a short string identifying the kind of concept", not centrally registered; example values `BigQuery Table`, `BigQuery Dataset`, `API Endpoint`, `Metric`, `Playbook`, `Reference`, `Attested Computation`. "`type` is the only always-required key; a concept carrying just `type` is fully conformant (§11)." Consumers "MUST tolerate unknown types gracefully".
- **Recommended:** `title`, `description` (one sentence), `resource` (URI of the underlying asset; absent for abstract concepts), `tags` (YAML list).
- **Extensions:** "Producers MAY include any additional keys. Consumers SHOULD preserve unknown keys when round-tripping and MUST NOT reject documents with unrecognized fields." (Live example: `bundles/acme_retail/metrics/gross-margin.md` carries a non-spec `not:` key with `term`/`why`/`instead`.)

**Provenance / trust / lifecycle families** (§5, all optional; every timestamp is "an ISO 8601 datetime with an explicit UTC offset"):
- `sources`: list; per entry `resource` **REQUIRED** (absolute URL, bundle-relative path, or a *scope descriptor* like `all queries in BigQuery project X`), plus optional `id` (stable key for per-claim attribution), `title`, and credibility signals `author`, `usage_count`, `last_modified`. Sibling `usage_window: { from, to }` frames all `usage_count`s. "OKF records the signals, not a verdict" — no credibility score is stored, it is inferred.
- Per-claim attribution uses **markdown footnotes keyed to `sources[].id`**: `…sharded daily as `events_YYYYMMDD`.[^ga4-schema]` + `[^ga4-schema]: GA4 BigQuery Export schema`. "The footnote label is the join key into `sources`"; keyed rather than positional "because agents constantly rewrite these documents".
- Lineage: "expressed through links, not a dedicated field"; when a `sources[].resource` points at another concept, the derivation edge is already in the bundle graph. "Deeper lineage (an explicit external `derived_from`, or data lineage) is out of scope for v0.2."
- `generated: { by, at }` — `by` REQUIRED within it, an *actor*; `at` marks "the content's last meaningful change".
- `verified` — list of `{ by, at }` events; "a bare mapping" MUST be treated as a one-element list.
- **Trust tiers** (§5.3, derived not stored): no `verified` ⇒ **unverified**; non-`human:` actors only ⇒ **machine-confirmed**; a `human:<id>` actor ⇒ **human-reviewed**. "Trust tiers are advisory signals, not access control."
- `status: draft | stable | deprecated`; absent ⇒ `stable`.
- `stale_after: <ISO instant>` — "A concept is stale when `now >= stale_after`"; absolute instant, not a TTL.

**Actor convention** (§7): `<producer>/<version>` for agents/tools (`reference_agent/gemini-2.5-pro`), `human:<id>`, `process:<id>`. Producers MUST use the `human:` prefix for hand-authored/human-confirmed content because trust classification keys off it.

**Identifier scheme.** There is none beyond the filesystem: Concept ID = bundle-relative path minus `.md` (§2). No UUIDs, URNs, or global namespace. `resource` optionally carries "a URI that uniquely identifies the underlying asset". `sources[].id` is a document-local key only.

**Linking model** (§6.1): ordinary markdown links, two accepted forms — bundle-relative absolute (`[customers](/tables/customers.md)`, **recommended**, "stable when documents are moved within their subdirectory") and plain relative (`./other.md`). "A link from concept A to concept B asserts a *relationship*. The specific kind (parent/child, references, joins-with, depends-on) is conveyed by the surrounding prose, not by the link itself" — consumers building graphs "treat all links as directed edges of an untyped relationship". "Consumers MUST tolerate broken links… it may simply represent not-yet-written knowledge." §6.2 lists path-valued fields: `resource`, `sources[].resource`, `computation`, `executor.resource`, `attester.resource`. §6.3: `references/` is a *convention* for mirroring external material, executors, attesters.

**Conventional body headings** (§4.2): `# Schema`, `# Examples`, `# Computation`. No required sections.

**Attested Computation** (§10): `type: Attested Computation` concept carries `runtime` (REQUIRED for this type; e.g. `bigquery`, `postgres`, `dbt`, `python`, `Looker`), `parameters` (`{ name, type, required }` entries), optional `computation` (path to a computation file; absent ⇒ the body `# Computation` fence is the computation), `executor: { resource, receipt: [...] }`, `attester: { resource }` ("deterministic check… code (no LLM) that takes a receipt and returns a verdict", runs consumer-side). "The agent MAY only supply *values* for the declared `parameters`; it MUST NOT author or edit the computation." Receipts/verdicts are runtime artifacts, "**not** stored in the bundle".

**Versioning** (§12): document specifies version **0.2**; `<major>.<minor>`, minor = backward-compatible additions, major = breaking. "Bundles MAY declare the version they target with `okf_version: \"0.2\"` in a bundle-root `index.md` frontmatter block (the only place frontmatter is permitted in an `index.md`)." Unknown version ⇒ best-effort consumption, not refusal. (Checked: `bundles/acme_retail/index.md` carries no frontmatter and no `okf_version`.) §13 breaking changes from v0.1: `timestamp` → `generated.at`; body `# Citations` list → `sources`.

**Conformance** (§11): a bundle is conformant if every non-reserved `.md` has parseable YAML frontmatter, every frontmatter has a non-empty `type`, and reserved files follow §8/§9. Consumers MUST NOT reject a bundle for missing optional fields, unknown `type`, unknown extra keys, broken cross-links, or missing `index.md`.

**Chunking / embeddings: none.** Searching the full 1012-line spec surfaces no chunk, embedding, vector, token-budget, or similarity field. The only retrieval affordance is *progressive disclosure* via `index.md` hierarchies plus queryable frontmatter (`type`, `tags`, `status`, `generated`, `verified`, `stale_after`).

### Real example document (verbatim, `bundles/acme_retail/metrics/gross-margin.md`)

```markdown
---
type: Metric
title: Gross Margin
description: Gross margin for a period, per Acme's FY2026 Cost Allocation Standard (product cost + inbound fulfillment + outbound shipping + payment fees).
tags: [finance, margin, headline-metric]
generated: { by: reference_agent/gemini-2.5-pro, at: 2026-06-30T14:00:00Z }
verified:
  - { by: human:jsmith@acme, at: 2026-07-01T09:00:00Z }
status: stable
stale_after: 2026-12-31T00:00:00Z
not:
  - term: "revenue minus product cost only"
    why: "that is the pre-FY2026 definition (see gross-margin-legacy). It excluded fulfillment, shipping, and payment fees, and could not be reconciled to the general ledger."
    instead: "revenue minus full COGS (product cost + inbound fulfillment + outbound shipping + payment fees)"
sources:
  - id: margin-standard
    resource: policies/margin-standard.md
    title: Cost Allocation & Margin Standard (FY2026)
    author: human:jsmith@acme
    last_modified: 2026-06-15T00:00:00Z
  - id: revenue-policy
    resource: policies/revenue-recognition.md
    title: Revenue Recognition Policy (FY2026)
    author: human:jsmith@acme
    last_modified: 2026-06-15T00:00:00Z
---

# Definition

**Not:** revenue minus product cost only (that was the pre-2026 formula; see [`gross-margin-legacy`](./gross-margin-legacy.md)).

Gross margin for a period equals recognized [Revenue](./revenue.md) minus **full COGS**, where full COGS is the sum of product cost, inbound fulfillment cost, outbound shipping cost, and payment processing fees. [^margin-standard]

```
gross_margin(period) = revenue(period) - cogs_full(period)
```

The sanctioned computation is [`computations/gross-margin-period.md`](../computations/gross-margin-period.md). Consumers MUST run and attest that computation.

# What changed in FY2026

Prior to 2026-02-01, Acme's gross-margin definition included only product cost, excluding fulfillment, shipping, and payment fees. That legacy definition is preserved in [`metrics/gross-margin-legacy.md`](./gross-margin-legacy.md) as `status: deprecated` for historical query reproducibility.

The switch reduced reported gross margin by roughly 4-6 percentage points depending on category. It also brought the number in line with the general ledger, closing a long-standing reconciliation gap.

# Trust and freshness

- **Verified:** VP Finance sign-off on 2026-07-01, against the FY2026 margin standard.
- **Stale after 2026-12-31:** the cost-allocation standard is reviewed annually. Consumers must re-verify against the FY2027 standard before serving.

[^margin-standard]: Cost Allocation & Margin Standard (FY2026)
[^revenue-policy]: Revenue Recognition Policy (FY2026)
```

## Tooling

- **Reference implementation: Python, install-from-source only.** `pyproject.toml` → `name = "reference-agent"`, `version = "0.1.0"`, `requires-python = ">=3.11"`, deps `google-adk>=2.0`, `google-cloud-bigquery>=3.20`, `pyyaml>=6.0`, `pydantic>=2.0`, `markdownify>=0.11`; console script `reference-agent = reference_agent.cli:main`. README install: `python3.13 -m venv .venv` then `.venv/bin/pip install -e .[dev]`.
- **Not published.** `https://pypi.org/pypi/reference-agent/json` → HTTP 404; `https://pypi.org/pypi/open-knowledge-format/json` → HTTP 404. No npm/crates artifact is referenced anywhere in the repo; there is no JS/Rust/Go SDK in-tree (repo language is reported as HTML because of the generated `viz.html` files).
- **CLI subcommands** (`src/reference_agent/cli.py`): `enrich` (`--source bq`, `--dataset project.dataset`, `--billing-project`, `--out`, `--concept`, `--model`, `--web-seed`, `--web-seed-file`, `--web-max-pages` default 100, `--web-allowed-host`, `--no-web`) and `visualize` (`--bundle`, `--out`, `--name`). **There is no `validate`/`lint`/`check` subcommand.**
- **Closest thing to a validator:** `src/reference_agent/bundle/document.py` — `OKFDocument.parse/serialize/validate` with `REQUIRED_FRONTMATTER_KEYS = ("type",)`, plus spec-implementing helpers `normalize_verified()` (§5.2), `trust_tier()` (§5.3), `is_stale()` (§5.5). It also subclasses `yaml.SafeLoader` to strip the YAML 1.1 timestamp resolver so frontmatter timestamps round-trip as the author wrote them. Library-level only; you would import it, not run it.
- **Consumer PoC:** `visualize` emits a self-contained `viz.html` (Cytoscape.js graph + `marked` markdown rendering, both from CDN) with type filter, tag/title search, and "Cited by" backlinks computed from the reverse link graph.
- **Connector:** `connectors/gcp-knowledge-catalog.md` documents pushing/pulling a bundle to a Dataplex **Knowledge Catalog** EntryGroup using **`kcmd`** from `GoogleCloudPlatform/knowledge-catalog/toolbox/mdcode` (TypeScript, built with `npm install && npm run build`, driven with Bun). Explicitly lossy: only 7 frontmatter keys (`title`, `description`, `tags`, `resource` natively; `type`, `generated`, `sources` on a custom `okf` aspect), only `.md` files, cross-links "resolve to nothing".
- Tests: `pytest`, `testpaths = ["tests"]`.
- Modules in-tree: `agent.py`, `runner.py`, `cli.py`, `bundle/{document,index,paths,synthesizer}.py`, `sources/` (BigQuery), `tools/`, `web/`, `viewer/`, `prompts/`.

## Gaps a consumer must fill

Explicit non-goals and deferrals, with the spec's own words:

- **Storage / serving / query infrastructure** — §1 non-goal: "Prescribing storage, serving, or query infrastructure." No API, no index format, no server.
- **Retrieval / search / ranking** — nothing specified. "a search index" is listed only as an example consumer (README). You build the index, the query language, and relevance.
- **Embeddings & chunking** — absent from the spec entirely. No chunk boundaries, no embedding fields, no vector metadata, no token-budget hints. If you RAG over OKF, you own chunking (natural unit: one concept, or one `#` section) and vector storage.
- **Access control** — §5.3: "Trust tiers are advisory signals, not access control." No ACL, no visibility, no redaction fields. The Knowledge Catalog connector notes "**No entry-level access control**" on the Dataplex side too.
- **Typed relationships / lineage** — links are untyped (§6.1); relationship kind lives in prose. "Deeper lineage (an explicit external `derived_from`, or data lineage) is out of scope for v0.2" (§5.1). A call graph or dependency graph must encode edge semantics outside OKF.
- **Validation & conformance tooling** — no schema file (no JSON Schema, no protobuf), no validator CLI, no schema registry ("There is no schema registry, no central authority, and no required tooling"). You write the checker; `document.py` gives ~120 lines to copy.
- **Type taxonomy** — §1 non-goal: "Defining a fixed taxonomy of concept types." `type` values are free strings; two bundles will disagree.
- **Domain schemas** — "Replacing domain-specific schemas (Avro, Protobuf, OpenAPI…). OKF *references* them; it does not subsume them."
- **The attestation runtime** — §12 deferred: "The full runtime protocol: receipt and verdict wire formats, and the attestation lifecycle around a run"; "The attester ABI, portability, and sandboxing"; "Attestation caching"; semantic-layer templates (Looker, dbt). Also §1: "Specifying a packaging or invocation standard for the code an executor or attester points at. OKF fixes the interface, not the packaging."
- **Identity/uniqueness across bundles** — concept IDs are paths; merging two bundles or renaming a file silently rewrites identity. Nothing in OKF resolves collisions or tracks renames (git does).
- **Conflict/merge, deletion, GC** — not addressed; the connector doc says "Treat git as authoritative".
- **Freshness enforcement** — `stale_after` is a datum; recomputing, alerting, and re-verification loops are yours.

## Consumption by LLM agents

OKF's agent story is *context-window discipline plus frontmatter-gated trust*, not retrieval:

- **Progressive disclosure** (§8, README): "Auto-generated `index.md` files let an agent or human navigate the hierarchy one level at a time instead of loading the entire bundle into context." `index.md` entries carry the linked concept's `description`, so an agent can decide what to open from the listing alone. Consumers "MAY synthesize one on the fly when none is present".
- **Direct ingestion, no SDK** (README): "An engineer can `cat` a concept; an LLM can ingest it verbatim into context." "Parseable by agents without bespoke SDKs" (§1).
- **Deliberate structured/unstructured split** (README): frontmatter holds "the few fields you want to query, filter, or index on (`type`, `resource`, `tags`, `generated`, `status`)"; the body holds "the prose, schemas, and example queries that LLMs and humans actually read". §4.2 pushes producers toward headings/tables/fences "since structure aids both human reading and agent retrieval".
- **Graph traversal**: cross-links are the agent's expansion frontier; consumers typically build a directed untyped graph (the bundled viewer does exactly this, plus reverse-edge "Cited by" backlinks).
- **Agents as first-class producers**: §1 — a corpus "is **continuously written and maintained by agents**"; the actor convention (§7) makes agent-authored content (`reference_agent/gemini-2.5-pro`) distinguishable from `human:`/`process:` content, and trust tiers (§5.3) let a consuming agent prefer human-reviewed concepts.
- **Guardrails on agent improvisation** (§10.3): "The agent MAY only supply *values* for the declared `parameters`; it MUST NOT author or edit the computation." The attester compares the receipt's `executed_sql`/`compiled_sql` against the sanctioned computation bound with the claimed parameters, so "a rewritten query, a swapped computation file, or a mutated dependency fails the check" — "A typed, parameter-only surface is what makes 'did the sanctioned thing run' a mechanical comparison rather than a judgement call."
- **Consumer gating loop** (§10.5, informative): discover by `type: Attested Computation` → load contract → parameterize → execute → attest → **gate**: "refuse to display a failing attestation; warn or refuse when `now >= stale_after`. On success, surface the verdict (for example a link to the job log) so trust is visible."
- **Verification vs attestation** (§10.6): `verified` is doc-level and slow ("confirms the *definition* still matches policy"); attestation is per-run and not stored.

### Relevance to a context manager for coding agents

- Reusable as-is: concept-per-file + `index.md` progressive disclosure + frontmatter families (`type`, `status`, `generated`, `verified`, `stale_after`, `sources`) as the long-term document layer; `trust_tier`/`is_stale` are ~30 lines each.
- Must be supplied by you: chunking, embeddings, pgvector schema, retrieval/ranking, an identifier scheme stable under file renames, and typed edges for a *programmatic* call/import graph (OKF links are deliberately untyped and prose-qualified — graphify output does not fit the OKF link model without an extension key).
- The extension mechanism ("Producers MAY include any additional keys… consumers MUST NOT reject") is the sanctioned place to hang chunk IDs, embedding pointers, or graph edge types without leaving conformance.
